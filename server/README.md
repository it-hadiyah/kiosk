# خادم الكتالوج + لوحة تحكم كيوسك هدية

خادم صغير **بدون أي اعتماديات** (Node ≥ 18) يخدم:
- لوحة التحكم على `/admin/`
- الكتالوج المنشور على `GET /api/catalog` (يقرؤه التطبيق)
- الصور على `/uploads/…`

## التشغيل
```bash
cd server
ADMIN_PASSWORD='كلمة-مرور-قوية' PORT=8080 node server.js
# لوحة التحكم:  http://localhost:8080/admin/
```
- إن لم تضبط `ADMIN_PASSWORD` تُولَّد كلمة مرور مؤقتة وتُطبع في الطرفية.
- البيانات في `DATA_DIR` (الافتراضي `server/data`): `catalog.json` (المنشور) · `draft.json` (المسودة) · `history/` (آخر 30 نسخة) · `uploads/`.
- أول تشغيل ينسخ البيانات التجريبية من `seed/`.

### Docker
```bash
docker build -t hadiyah-admin .
docker run -d -p 8080:8080 -v hadiyah-data:/data -e ADMIN_PASSWORD='...' hadiyah-admin
```

## ربط التطبيق بالخادم
أثناء بناء التطبيق:
```bash
flutter build apk --release --dart-define=CATALOG_URL=https://your-server.example.com
```
- التطبيق يجلب الكتالوج عند التشغيل، كل 5 دقائق، وبعد كل جلسة، ويحفظ نسخة محلية والصور للعمل بدون إنترنت.
- بدون `CATALOG_URL` يعمل بالكتالوج المضمّن (`lib/data/default_catalog.dart`).
- يُنصح باستخدام **HTTPS**. (التطبيق يسمح بـ HTTP للتجارب فقط.)

## سير العمل في اللوحة
1. عدّل (البرامج / الكتالوجات / الصفحة الرئيسية / الإعدادات) — الحفظ تلقائي كمسودة.
2. راجع المعاينة ثم **نشر التغييرات** ← يظهر في الكيوسكات خلال دقائق أو بعد انتهاء الجلسة الحالية.
3. أخطأت؟ **النشر والنسخ ← استرجاع** نسخة سابقة ثم انشرها.

### النشر والإصدارات (v2)
- **فحص ما قبل النشر** (`GET /api/admin/preflight`): سلامة البيانات، ملفات الصور، الترجمات، عناصر غير موضوعة، كتالوجات فارغة، عناصر مؤرشفة في الرئيسية، أجهزة غير معروفة. البنود الحمراء **تمنع** النشر والصفراء تنبيهات.
- **أرقام الإصدارات**: كل نشر فعلي يأخذ رقماً متسلسلاً (`release`) ويُسجَّل في `data/releases.json` (الرقم، الوقت، الدور، قائمة التغييرات) ويُحفظ له لقطة في `data/history/`. النشر دون تغيير في المحتوى لا ينشئ إصداراً جديداً.
- **المقارنة والاسترجاع**: يمكن مقارنة أي نسخة سابقة بالمسودة الحالية؛ الاسترجاع يحمّل النسخة إلى **المسودة فقط** ولا ينشرها.
- **تجاهل المسودة** (`POST /api/admin/discard`): يعيد المسودة إلى المنشور.
- **وصول الإصدار للأجهزة**: لوحة «النظرة العامة» وصفحة النشر تعرضان الإصدار الذي استلمه كل جهاز (من آخر جلب للكتالوج) وتنبّهان لجهاز متصل لم يستلم آخر إصدار.
- **الأرشفة** بدل الحذف: البرنامج/الكتالوج المؤرشف يُخفى عن المتبرعين دائماً، ولا يُحذف نهائياً إلا بعد إزالته من كل الأماكن.

## الأدوار والصلاحيات
كلمة مرور لكل دور (الأدوار غير المضبوطة تُعطَّل). تُطبَّق الصلاحيات في الخادم وليس في الواجهة فقط:

| المتغير | الدور | يستطيع |
|---|---|---|
| `ADMIN_PASSWORD` | مدير النظام | كل شيء |
| `MANAGER_PASSWORD` | مدير المحتوى | + النشر والاسترجاع والإعدادات العامة وحذف الصور غير المستخدمة وسجل التدقيق والإحصائيات |
| `EDITOR_PASSWORD` | محرّر | تعديل المسودة (برامج/كتالوجات/رئيسية/الأكثر رواجاً) ورفع الصور فقط |
| `VIEWER_PASSWORD` | مشاهد | قراءة ومعاينة فقط |

```
ADMIN_PASSWORD=... MANAGER_PASSWORD=... EDITOR_PASSWORD=... VIEWER_PASSWORD=... node server.js
```

## سجل التدقيق والوسائط والإحصائيات
- **سجل التدقيق** (`data/audit.jsonl`): من دخل/عدّل/نشر/رفع/حذف ومتى، مع ملخص التغيير. يظهر في «النشر والنسخ».
- **الوسائط**: تبويب «الوسائط» يعرض كل الصور وأين تُستخدم، ويمنع حذف صورة مستخدمة (في المسودة أو المنشور).
- **إحصائيات المحاكاة** (`data/analytics.json`): يرسل الكيوسك أحداثاً (بدء جلسة، اختيار برنامج، مبلغ تجريبي، إكمال المحاكاة، ترك) إلى `POST /api/events`. بلا أي بيانات شخصية أو مالية، وكلها موسومة «بيانات تجريبية». كما يُسجَّل آخر اتصال لكل جهاز وإصدار التطبيق.

## لوحة المؤشرات
تبويب «لوحة المؤشرات» (لمدير المحتوى فأعلى) يعرض لكل فترة (اليوم / 7 أيام / 30 يوماً / الكل): إجمالي التبرعات المكتملة والمبالغ، الجلسات ومعدلي الإكمال والترك ومتوسط المدة، رسماً يومياً، **البرامج الأكثر تبرعاً**، **الكتالوجات الأكثر زيارة والأكثر تبرعاً**، وجدولاً **لكل جهاز** (اضغط اسم الجهاز لعرض كل المؤشرات له وحده). كل الأرقام من **محاكاة الدفع** وموسومة «بيانات تجريبية». يُحسب اليوم بتوقيت الجمعية (`TZ_OFFSET_HOURS`، الافتراضي 3). تُحفظ التفاصيل اليومية 120 يوماً. الأرقام تبدأ من وقت تحديث التطبيق (الأحداث الجديدة فقط).

## تفعيل الكيوسكات (الأجهزة)
كل كيوسك يُفعَّل بـ **معرف جلسة** من 8 أرقام تنشئه من لوحة التحكم ← «الأجهزة» ← «فتح جلسة جديدة». عند أول تشغيل للتطبيق (أو بعد إنهاء جلسته) تظهر شاشة تطلب **معرف الجلسة** و**اسم الكيوسك**.
- المعرف يعمل **مرة واحدة** ويصلح 24 ساعة، ثم يصبح الكيوسك «نشطاً» ويظهر في القائمة بحالته (متصل/غير متصل)، وإصدار التطبيق، وعدد جلسات المحاكاة.
- **نقل الكيوسك إلى مكان آخر:** من اللوحة «إنهاء الجلسة» (أو من الكيوسك نفسه: 5 لمسات في الزاوية العلوية اليسرى ← «إنهاء الجلسة») ثم افتح جلسة جديدة بمعرف جديد.
- عند إنهاء الجلسة من اللوحة يعود الكيوسك إلى شاشة التفعيل خلال دقيقة (عند أول تحديث للكتالوج).
- رمز الكيوسك موقّع ومحفوظ على الجهاز، ولا يمنح أي صلاحية إدارة. مفتاح التوقيع محفوظ في `data/secret.key` فلا تسقط الجلسات عند إعادة تشغيل الخادم (احتفظ بهذا الملف مع النسخ الاحتياطي).
- صلاحية إدارة الأجهزة: مدير المحتوى ومدير النظام فقط.
- **ظهور البرامج حسب الجهاز:** في تعديل أي برنامج أو كتالوج بطاقة «الأجهزة التي يظهر عليها»: **كل الأجهزة** (الافتراضي) أو **أجهزة محددة**. يُطبَّق التحديد في الخادم: كل كيوسك يستلم كتالوجاً مفلتراً لجهازه فقط، ويُحذف معه كل ما يشير للعناصر المخفية (الرئيسية، الكتالوجات، الأكثر رواجاً)، والكتالوج الذي فرغ بالتصفية يختفي. الجهاز يُعرَّف بمعرّفه الثابت (لا بالجلسة)، فيبقى التحديد صالحاً إذا نُقل الكيوسك وفُتحت له جلسة جديدة. الأجهزة غير المفعّلة والنسخ القديمة ترى العناصر المفتوحة للكل فقط.

## الأمان
- رمز دخول موقّع (HMAC) صالح 12 ساعة ويحمل الدور، وحد 5 محاولات خاطئة في الدقيقة. المصادقة بترويسة `Authorization: Bearer` (لا ملفات تعريف ارتباط) فلا يوجد CSRF.
- حقل الأحداث العام محدود الحجم (2KB) والمعدل (300/دقيقة/عنوان) ويقبل أنواعاً معروفة فقط.
- رفع الصور: jpg/png/webp فقط (فحص محتوى الملف) حتى 6MB.
- شغّله خلف HTTPS (Nginx/Caddy/سحابة) ولا تكشف المنفذ مباشرة للإنترنت.
